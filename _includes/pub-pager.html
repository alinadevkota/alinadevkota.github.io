{% comment %} Previous / next for a paper page. Not the theme's post_pagination.html, which walks the collection in date ASCENDING order and so points "Previous" at the older paper - the opposite direction to the index pane, which is newest first. These neighbours are taken from the same ordering the pane uses, so the two agree. Rendered server-side for the default (date) grouping; the index script rewrites it when the pane is regrouped or filtered, so the pager always follows whatever order is on screen. Links are relative, so in-place navigation can intercept them - the theme's version emitted absolute site URLs, which failed the same-origin check and forced a full reload. {% endcomment %} {% assign ordered = site.publications | sort: "date" | reverse %} {% assign here = 0 %} {% for p in ordered %}{% if p.url == page.url %}{% assign here = forloop.index0 %}{% endif %}{% endfor %} {% assign prev_i = here | minus: 1 %} {% assign next_i = here | plus: 1 %} {% assign last_i = ordered | size | minus: 1 %}
